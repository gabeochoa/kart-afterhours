CART CHAOS — menu UI mock, Memphis '93

Matched to the reference you pointed at. The grammar: deep purple ground with faint tonal blocks behind everything, pastel-bright accents (orchid / sky / mint / butter), shapes that are as often outlined as filled, stripe fills inside triangles and circles, squiggles and zigzags scattered loose, and pixel-glitch type with chromatic offset — the "1993" treatment.

PALETTE

Cars and weapons are drawn in the same language — same 3px ink outline, same four accents, stripe fills instead of shading — so they read as part of the set rather than imported. Sheet at the bottom.

SPRITE DIRECTION — cars & weapons

Same rules as the chrome, which is the point: 3px ink outline, flat fill from the four accents, stripes instead of shading, no gradients, no anti-aliasing. Write those down once and anything drawn later fits automatically — including the tonal thumbnails on the track screen.

What's in the spritesheet today: almost nothing. resources/images/spritesheet.png is 1024×1024 and roughly 90% empty. The used corner holds a few small greyscale items — a cannon, an AK, a crosshair, a cat, a fridge, some explosion frames — drawn semi-realistically with no shared palette or outline weight. That's also the source of the stray gun floating at top-centre of every menu: one of these, placed by a system that was never finished. So "make the cars and weapons fit in" is a drawing job in any direction; there's no existing style to preserve, which makes this the cheap moment to set one.

WHAT THIS COSTS — engine gap analysis

Cheapest of the four passes. Flat fills, hard rectangles and solid borders are what the UI plugin draws natively — no gloss, no bevels, no soft shadows, no rounded display font.

Design elementStatusDetail
Flat fill + thin bright borderBUILDABLE Background colour plus a border. Native today; this is the whole look.
Hard offset shadowBUILDABLE with_shadow(ShadowStyle, offset_x, offset_y) at component_config.h:753, unused. No blur wanted — the easy case.
Stripe fillsBUILDABLE A tiling sprite, or with_on_draw_bg (new in the bump). Reused for meters, the winner bar, thumbnails and selection.
Selection: stripes + ringBUILDABLE Border swap plus the stripe background. No scale or rotation needed, which sidesteps the hit-testing question entirely.
Confetti geometryBUILDABLE Static triangles, rings, squiggles — sprites or draw calls, laid out once per screen. No particle system.
Tabs, toggles, sliders, dropdownsBUILDABLE tab_container, toggle_switch, slider, dropdown — all ship, mostly unused.
Grey-out until readyBUILDABLE with_disabled() — zero calls today; the exact case the gaps doc first asked for.
Pause cardBUILDABLEmodal ships, unused.
Chromatic-offset titleBUILDABLE Draw the label three times at small offsets in three colours. Cheap, and with_styled_label (new in the bump) may do it in one.
Tilted karts on the menuSIDESTEPPED Bake the rotation into the sprite rather than rotating a UI element. Avoids the unresolved question of whether hit-testing respects rotation.
Car + weapon spritesNEEDS ART The real cost, unavoidable in any direction. This style is the easiest of the four to draw consistently — "flat fill, ink outline, stripes not shading" is a rule anyone can follow and check.
Pixel display fontNEEDS A FONT Wants a blocky bitmap face. The bundled CJK mono is closer than you'd think — it's already monospace and blocky — so this may be the one direction that needs no new font. Worth testing before sourcing anything.
Real track thumbnailsNEEDS CARE generate_map_preview can render real maps, but it builds each 100k units offscreen and deletes anything with a Transform in the preview rect. Harden first. Stripe-fill blocks work fine until then.

Two places the mock promises what the code doesn't do, both on the TODO: Options says "SAVED AUTOMATICALLY" (item 8 — settings persist on exit only) and the podium implies clean per-round scores (item 3 — trackers never reset, so round 2 inherits round 1).
